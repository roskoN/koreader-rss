# Contributing

Contributions are welcome through pull requests. The `main` branch is
maintainer-controlled: contributors should not push directly to it.

## Workflow

1. Fork the repository and create a focused branch from `main`.
2. Make the smallest coherent change and add or update tests where applicable.
3. Run the relevant local checks before opening a pull request:

   ```sh
   make test
   make validate
   ```

4. Push the branch to your fork and open a pull request against `main`.
5. Wait for required CI checks and maintainer review. Do not force-push shared
   branches or commit generated build output.

The CI workflow runs Rust formatting, Clippy, workspace tests, interruption and
cache validation, Lua syntax checks, and an ARMv7/QEMU smoke test. Live RSS
checks and real-Kindle checks are intentionally not required for every pull
request.

## Release process

Maintainers publish releases by creating and pushing a version tag such as
`v0.0.2`. GitHub Actions builds the ARMv7 Kindle package and attaches a ZIP
archive to the GitHub release. Release archives are generated by CI; do not
commit `dist/` or release binaries.
